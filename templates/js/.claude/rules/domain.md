# DOMAIN.md 운영 규칙

`DOMAIN.md` 는 **의미(semantics) 전용 문서**다. 구조는 codegraph와 스키마 파일이 담당한다.
역할 분담 전체는 `@.claude/rules/knowledge.md` 참조.

## 무엇을 적고 무엇을 적지 않는가

| 적는다 | 적지 않는다 (codegraph·스키마에 물어볼 것) |
|--------|------------------------------------------|
| enum·union 값이 무슨 뜻이고 언제 전이하는가 | 엔티티·함수가 어디 있는가 |
| 미들웨어·훅·리스너가 무슨 부수효과를 내는가 | 누가 무엇을 호출하는가 |
| 도메인 용어·팀 내부 슬랭 | 필드 목록·타입·관계 |
| 여러 모듈에 흩어진 비즈니스 규칙 | 계층 트리·의존 그래프 |
| 과거 사고 지점 (변경 시 주의사항) | 이걸 바꾸면 어디가 깨지나 |
| 모델 → 실제 테이블명 매핑 (`@@map`) | |

**구조를 문서에 박제하지 마라.** 그 순간부터 낡는다. 스키마 파일이 진실의 원천이고,
거기서 재도출 가능한 것은 재도출한다.

## 에이전트별 의무

| 에이전트 | 의무 |
|---------|------|
| **analyst** | 구조 파악은 codegraph 우선. 작업 대상의 `DOMAIN.md`에서 상태값 의미·부수효과·용어를 확인. 스키마를 건드리는 작업이면 **부수효과 표 확인은 필수** |
| **coder** | 의미가 바뀌는 변경(enum·union·`as const`·`@@map`·훅)을 했으면 같은 커밋에서 `DOMAIN.md` 갱신 |
| **reviewer** | 의미 변화 대비 문서 갱신 여부를 **게이트로 검증**. 미갱신은 PASS 불가 |

## 갱신 트리거

게이트가 자동으로 잡아주지만, 무엇이 트리거인지 알고 움직인다.

```
TS enum / Prisma enum 값 변경   → 상태값 표의 '의미 / 전이 조건' 채우기
as const 상수 객체 키 변경       → 같음
문자열 리터럴 union 타입 변경     → 같음
Prisma @@map 변경               → 모델 → 테이블 매핑 표 갱신
미들웨어·훅·리스너 추가·변경      → '부수효과' 표 채우기
새 도메인 용어·슬랭 등장          → 루트 DOMAIN.md 용어 사전
사고·장애가 났던 지점             → '변경 시 주의사항'
```

앞의 넷은 `domain-gate.py` 가 선언 블록 지문 비교로 감지해 커밋을 막는다.
뒤의 셋은 기계가 알 수 없으니 사람과 에이전트가 판단해서 남긴다.

## 값 목록은 손으로 적지 마라

값과 위치는 스키마 파일에 이미 있다. 손으로 옮겨 적으면 틀린다.
사람이 채울 것은 **'의미' 열뿐**이다.

## DOMAIN.md가 없거나 낡았을 때

```bash
# 스켈레톤 생성 (이미 있으면 건너뜀)
bash ~/harness-init/scripts/domain-init.sh

# 신선도 점검 — 소스보다 며칠 뒤처졌는지
python3 .claude/scripts/domain-freshness.py .
```

세션 시작 시 낡은 문서 목록이 컨텍스트로 자동 주입된다.
그 목록에 있는 문서의 내용은 **근거로 쓰기 전에 코드로 교차 확인**한다.
